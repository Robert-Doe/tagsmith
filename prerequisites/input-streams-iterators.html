The Big Analogy

Imagine reading a scroll through a narrow viewing window cut into a piece of cardboard. The scroll doesn't move — you slide the cardboard along it, one character-width at a time. At any instant you can only see what's directly under the window: one character. You always know exactly how far you've slid (your position), and you know you're done when there's no more scroll left to slide onto.

That's an input stream: a sequence of characters plus a moving position marker. The spec calls the position marker's target the "current input character," and it defines the tokenizer's entire job as repeatedly asking one question: "consume the next input character — what is it, and what should I do because of it?"

Two moves, and only two

  • Peek — look at the character under the window without sliding the cardboard. Position doesn't change.
  • Consume — slide the cardboard forward by one and report what was under the window before you moved. Position advances by one.

Almost every sentence in the tokenization spec that starts with "Consume the next input character" is just this second move, over and over, tens of thousands of times per page load.

Knowing when you're out of scroll

There has to be a special answer for "there is no next character" — the spec calls this EOF (end-of-file), and it is treated as its own distinct signal, not as some particular character value like null or 0. Every state in the spec that reads input has to say what happens on EOF, separately from what happens on any real character.

Why this distinction matters later

In Module 1, the very first piece of real logic this whole course writes is exactly this EOF check — "is there a next character, or not" — because it turns out to be the single simplest correct behavior in the entire 68-state machine: no input, no work, just report "done."

Pseudocode shape

stream = characters of the input text
position = 0

function peek():
    if position >= length(stream): return EOF
    return stream[position]

function consume():
    c = peek()
    if c != EOF: position = position + 1
    return c

How this connects

This is the "input" half of a finite state machine's transition function. And because sometimes a state reads a character, changes its mind, and needs to "un-read" it, see Lookahead & Reconsume next.
