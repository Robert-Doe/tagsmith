PrerequisiteLookahead & Reconsume

The Big Analogy

You're reading a word out loud, finger sliding under each letter as you go: c...a...t. Then your finger lands on a space. You suddenly realize: "wait, that space isn't part of this word — it's the boundary before the next one." You don't un-see the space. You just slide your finger back under it and read it again, but this time with the mental rule "I'm now looking for the start of a new word," not "I'm still spelling cat."

That's reconsume. It shows up constantly in the tokenization spec as the exact phrase: "Reconsume the current input character in the <some other> state." It means: don't advance the input position, but do switch to a different state and process that same character again — this time under the new state's rules.

Three related but distinct moves

  • Consume — read the current character and move the position forward. (Covered in Input Streams & Iterators.)
  • Lookahead — peek at upcoming characters (sometimes several at once, e.g. checking if the next few characters spell DOCTYPE) without consuming any of them, purely to decide what to do.
  • Reconsume — take a character that was already consumed, don't advance the position again, and process it under a new state. The character gets "used" twice, by two different states, but the input position only ever moves once for it.
Why the spec needs this move at all

Without reconsume, every state that needs to hand off to another state based on "the character I just saw" would have to smuggle that character along as extra data. Reconsume avoids that: the next state just reads the input stream normally and gets the same character back, because the position marker never moved. It's a clean way to say "change your mind about how to interpret what you just read," using the same read mechanism every state already has.

Pseudocode shape

function reconsume(newState):
    position = position - 1   // put it back
    state = newState          // change how we'll interpret it
    // the main loop will now consume() this same character again

In practice, most real implementations don't literally decrement a position twice — they just skip calling consume() once and jump straight to the new state's logic with the character they already have in hand. Same effect, one fewer redundant read.

How this connects

Reconsume only makes sense once you already have a state machine to switch into and an input stream with a position to rewind. You won't need this move yet in Module 1 (it has no branching logic to reconsume from) — it becomes essential starting with the Data state in Module 3.
