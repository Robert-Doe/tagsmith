01 — The Big Analogy

The same security guard, one extra badge type

Module 5's guard is back, still only opening the door for one exact badge. But this room ("script data," standing in for <script> content) has one more rule taped to the wall: if you show up holding a badge that starts with an exclamation mark, the guard doesn't evaluate it at all — they immediately radio a *different, stricter* guard station down the hall and hand you off, no questions asked. That stricter station is Module 7's entire job. This module only builds the radio call.

02 — What Happens, Step by Step

  1. Script data behaves exactly like RAWTEXT for ordinary text: no character references, NUL is a parse error but still literal, EOF ends it.
  2. Seeing < switches to a less-than-sign state that now checks for three possibilities instead of Module 5's two.
  3. /: same as before — try to match a closing </script>.
  4. !: immediately emit both the < and ! as real tokens (not deferred!), then hand off entirely to the script-data-escape-start state.
  5. Anything else: literal <, reconsume, back to script data — unchanged from Module 5.
  6. The end-tag matching chain (open → name → appropriate-check) is exactly Module 5's mechanism, reused without modification.

04 — The Algorithm, Explained (pseudocode)

function SCRIPT_DATA_LESS_THAN_SIGN_STATE(tokenizer):
    next = tokenizer.peek()
    if next == '/':
        tokenizer.tempBuffer = ''
        tokenizer.consume()
        tokenizer.state = SCRIPT_DATA_END_TAG_OPEN
        return
    if next == '!':                          // NEW this module
        tokenizer.consume()
        emit CharacterToken('<')
        emit CharacterToken('!')
        tokenizer.state = SCRIPT_DATA_ESCAPE_START   // Module 7's room
        return
    emit CharacterToken('<')
    tokenizer.state = SCRIPT_DATA                // reconsume, unchanged

05 — Limits / What You Cannot Do Yet

Can't do yet

  • Tokenize a real <script>...<!--...-->...</script> block containing an actual HTML-style comment (Module 7)
  • Handle a nested <script> inside an escaped comment (Module 8)
  • Enter script data from real markup — <script> the opening tag itself needs Module 9

Can do

  • Correctly tokenize ordinary JavaScript source with no embedded comments
  • Correctly recognize a real closing </script> tag
  • Correctly hand off to the escape mechanism the instant <! appears

08 — There Are No Dumb Questions

Q: Why would a script tag ever legitimately contain "<!--" in real-world code?
A: Historically, to hide script content from browsers old enough to not understand the <script> tag at all — those ancient browsers would render anything inside an unrecognized tag as plain text, so authors wrapped script bodies in an HTML comment, which those old browsers would correctly skip, while script-aware browsers were taught to specifically recognize and ignore that wrapping. Module 7 is that recognition mechanism.
Q: Is this "hide the script in a comment" trick still relevant today?
A: The browsers it was designed for are long gone, but the exact tokenizer behavior it required got permanently baked into the HTML spec — and real, currently-running JavaScript minifiers/bundlers and some server-rendering tools still occasionally emit this pattern, or content that accidentally resembles it, so a modern browser still has to handle it correctly today.
Q: Why does this module bother building the '!' handoff at all if Module 7 does all the real work?
A: Because "does the handoff happen correctly, with the right two tokens already emitted, landing in exactly the right state" is itself a fully specified, independently testable piece of behavior — and getting it right now means Module 7 can start from a verified, trustworthy entry point instead of having to re-verify this module's work as a side effect.

09 — What's Next

Module 7 builds SCRIPT_DATA_ESCAPE_START and its five sibling states — the actual comment-hiding mechanism this module only dialed the phone for. It's the most state-dense single concept in the entire spec: distinguishing "we're inside the hidden comment" from "we're inside a nested, literal <script> tag someone typed as plain text within that comment," using nothing but a count of consecutive dashes and letters.
